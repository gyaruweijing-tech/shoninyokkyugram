# PLAYBOOK — Routineが毎回従う手順

Routine（1時間ごとの自動発火）はこのファイルを読み、以下を **正確に** 実行する。
プロジェクト全体の方針は `../CLAUDE.md` に従う（トークン節約・必要ファイルだけ読む・完コピ）。

## このRunでやること：1機能だけ

### 手順
1. **選ぶ**: `auto-dev/ROADMAP.md` を読む。状態 `todo` の行のうち、**`auto-dev/refs/<ID>-*/` フォルダに画像が1枚以上入っている**もので、表の一番上の1件を選ぶ。
   - 対応フォルダ = `refs/` の中で、その行のIDから始まるフォルダ（例: `S03` → `refs/S03-archive/`）
   - `.gitkeep` しか入っていないフォルダは「スクショ無し」＝**着手しない**（想像で作らない）
   - 着手できる todo が1件も無い → 何もせず「スクショ待ち」と DEV_LOG に1行書いて終了。
2. **手本を見る**: そのフォルダ内の画像を **全部** Read（画像）で開く。ファイル名は無意味なことが多い（`IMG_1234.PNG` 等）ので、**中身を見てどのタブ/状態の画面かを自分で判別する**。
   - 1機能に複数枚あるのが普通（タブ・空状態・メニュー展開など）。1枚だけ見て実装しないこと。
   - ⚠️ **黒く塗り潰されている箇所は、プライバシー保護のためのマスクであり、UIの仕様ではない。**
     本家ではそこに**必ず何かの要素が入っている**（写真・動画のサムネ・アカウント名・数値など）。
     **黒い矩形をそのまま再現しては絶対にいけない。** 既存のダミーデータで埋めること
     （`comments-db.js` のペルソナ名・`kwImg()` で生成する画像・それらしい数値）。
     何が入るか分からない場合は、同じフォルダの `NOTES.md` を読む。無ければ周囲の文脈から推測する。
   - フォルダに **`NOTES.md` があれば必ず読む**。マスクで消えたUI情報（文言・バッジ・数値の書式など）や
     実装の注意が人間の手で書かれている。**スクショより NOTES.md の記述を優先する。**
3. **既存パターンを踏襲**: 新しい画面を作る場合は、**既にある似た画面の作り方を先に読む**（例: 設定画面=`js/settings.js`, 通知タブ=`js/views.js` の notif, プロフィール=`js/views.js`）。`switchView` の仕組み・view の markup が `index.html` にどう置かれているかを確認してから書く。
4. **実装（完コピ）**: スクショに寄せて1機能だけ実装する。
   - 依存ゼロ・ビルドなしを維持。読み込み順（comments-db→core→stories→feed→views→explore→settings→reels→main）を壊さない。
   - 文言追加は `comments-db.js`。ロジックは該当jsへ。
   - 「Coming soon」トーストを、実画面への遷移に置き換えるのが基本。
5. **検証**:
   - ロジック変更あり → ローカルで起動しブラウザ確認（該当画面に遷移して表示崩れ・エラーが無いか。console エラーを見る）。
   - 文言/軽微CSSのみ → 目視で十分。
   - 直せない・スクショと大きく違う・大規模改修が必要 → **完成扱いにしない**。状態を `blocked` にして理由を DEV_LOG に書く。
6. **状態更新**: `ROADMAP.md` の該当行の状態を `done`（or `blocked`）に書き換える。
7. **記録**: `auto-dev/DEV_LOG.md` の先頭に1エントリ追記（下の書式）。
8. **コミット & push**:
   - コミットメッセージ例: `auto-dev: S02 保存済み 画面を実装`
   - push 先ブランチ: **`auto-dev-work`**（自動コミットはここに溜める。人間が朝まとめてレビュー→mainへは手動）。
   - `git push -u origin auto-dev-work`。ネットワーク失敗時のみ 2s,4s,8s,16s でリトライ。
9. **終了**: 2件目に進まない。1 Run = 1機能。

## 厳守
- **1回に1機能だけ。** 欲張らない（利用制限と品質のため）。
- 既存の動いている機能を壊さない。壊しそうなら blocked。
- スクショが無いものは絶対に着手しない（想像で作らない）。
- API キー・秘密情報をコード/ログに書かない。
- `main` に直接 push しない。

## DEV_LOG 追記の書式
```
## YYYY-MM-DD HH:MM — <ID> <機能名>
- 結果: done / blocked / スクショ待ち
- やったこと: （1〜3行）
- 変更ファイル: index.html, js/views.js ...
- 詰まり/申し送り: （あれば）
```
